Selected work

AWS security lab

An environment built to practice both sides of the job: attacking a deliberately vulnerable web app, then finding the evidence in the logs.

Infrastructure
AWS VPC, EC2, S3, IAM
Tooling
Kali, Nmap, Metasploit, Nessus, DVWA
Visibility
Apache logs to S3, analyzed in Sumo Logic

Why I built it

Reading about an attack and seeing it in your own logs are different things. I wanted one place where I could launch an attack, scan for the weakness that made it possible, and then trace both in a SIEM, the same loop a detection engineer runs every day.

What's in it

  • Attack platform. Kali Linux running in Docker on an EC2 instance, with Nmap and Metasploit for reconnaissance and exploitation.
  • Target web server. DVWA, the Damn Vulnerable Web Application, on Ubuntu with Apache and MySQL.
  • Vulnerability scanner. Nessus on its own Ubuntu instance, scanning the target and reporting critical findings.
  • Log pipeline. A cron job syncs Apache logs to a private S3 bucket with the AWS CLI, using an instance role scoped to that bucket only.
  • Analysis. Sumo Logic ingests the bucket and drives dashboards and alerts for the attack traffic.

The whole environment is defined in Terraform, so I can tear it down when I'm not using it and stand it back up in minutes. See how the Terraform is built.

Problems I hit, and how I fixed them

  • Kali lost its setup on every restart

    Tools and configuration installed inside the container disappeared when it restarted.

    Fix: I committed the configured container to a custom image, so Nmap, Metasploit and my settings persist.

  • Logs weren't reaching S3

    Apache was writing logs, but nothing arrived in the bucket.

    Fix: I pointed Apache at a dedicated log directory and automated the sync to S3 with a cron job.

  • Nessus wouldn't install on Amazon Linux

    The installer wasn't compatible with the distribution.

    Fix: I rebuilt the scanner on Ubuntu, then confirmed it with a full scan of the target.

  • Nothing showed up in Sumo Logic

    The bucket had logs, but searches came back empty.

    Fix: I checked the S3 permissions, corrected the source configuration, and ran test queries until ingestion was confirmed.

What I'd add next

  • Network intrusion detection with Suricata or Snort, so attacks are visible below the application layer.
  • Longer, multi-stage attack scenarios to test whether the detections hold up across a full kill chain.
  • Automated response with EventBridge and Lambda, such as isolating an instance when an alert fires.
